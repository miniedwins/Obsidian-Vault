# SANBlaze Python API 專案架構分析報告

## 1. 總體架構概觀 (Architectural Overview)
本專案是一個高度模組化、資料驅動的 NVMe/儲存協定測試框架。它採用了「核心 + 多協定擴充 + 執行管理器」的三層設計模式。

### 核心分層架構：
1.  **資料定義層 (Data Definition Layer)**：以 `core.json` 為核心，定義了所有封包的 Bit/Byte 佈局，實現了與程式邏輯分離的宣告式解析機制。
2.  **核心 API 層 (Core API Layer)**：由 `api_core.py` 提供基礎的命令建構、執行 (`proc_write`) 與結果解析能力。
3.  **協定擴充層 (Protocol Layer)**：包含 `ocp`, `fdp`, `mi`, `dmtf`, `ieee` 等子模組，透過繼承核心 `API` 類別並動態注入 JSON 結構來支援各種標準。
4.  **執行管理層 (Execution Layer)**：由 `script/manager.py` 與 `sanblaze_test_api.py` 負責測試腳本的生命週期、狀態監控與 GUI 同步。

## 2. 核心組件說明

### 2.1 裝置抽象 (DUT - Device Under Test)
- **檔案**：`script/dut.py`, `dut.py`
- **職責**：提供統一的硬體操作介面。
- **特性**：支援動態擴充 (Dynamic Extension)，可在執行期將 MI, OCP 等模組掛載至 DUT 實例上，形成「全功能 DUT」。

### 2.2 測試執行管理 (Test Life-cycle)
- **檔案**：`script/manager.py` (`TestManager`), `sanblaze_test_api.py`
- **職責**：
    - 腳本啟動握手 (Wait for 'run')。
    - 異常捕獲與測試狀態 (Passed/Failed/Warning) 的自動寫回。
    - 即時監控系統日誌與 I/O 流量。
    - 訊號處理 (SIGINT, SIGUSR2) 以支援 GUI 的暫停/停止指令。

### 2.3 工作負載控制 (Workload Control)
- **檔案**：`script/workload.py`, `script/workload_thread.py`
- **職責**：管理底層 I/O 引擎。
- **特性**：支援多執行緒並發負載管理，並在測試結束時強制進行資料完整性校驗 (Abort Write Pass and Compare)。

### 2.4 配置與日誌 (Config & Logging)
- **檔案**：`config_utils.py`, `test_config.py`, `sanblaze_logging.py`
- **職責**：
    - 提供持久化的 JSON 設定管理與 CLI 互動選單。
    - 實作語義化日誌 (Action, Step, Detail, Note, Pass)，並同步輸出至終端與 REST tree。

## 3. 專案設計特點
- **資料驅動 (Data-Driven)**：指令格式與解析邏輯定義於 JSON 中，新增協定支援只需更新 JSON 檔。
- **高度解耦**：協定實作 (OCP/FDP) 與核心執行邏輯 (API) 解耦，腳本框架與具體的測試任務解耦。
- **硬體整合**：深度整合 `sb_i2c`、`setpci`、`lspci` 等工具，具備電源控制與暫存器監控能力。
- **容錯與還原**：具備強大的環境還原機制 (如 `namespace_restore`)，確保毀滅性測試後裝置能自動恢復原始狀態。

## 4. 目錄結構職責
- `/admin`, `/mi`, `/fdp`, `/ocp`, `/ieee`, `/dmtf`, `/tcg`：各類協定專屬 API 實作。
- `/script`：測試框架的核心邏輯 (Manager, Workload, DUT)。
- `/docs`：專案文件。
- `/dep`：依賴的 whl 套件包。
