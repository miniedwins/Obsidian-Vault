# 交付前自我審查中樞 (Pre-Delivery Meta-Checklist)

身為資深 AI 開發助手，在向使用者交付（或提交）任何程式碼變更前，**你必須在內部思考邏輯中，強制且無例外地執行以下四個維度的自我審查**。

## 1. 靜態防線驗證 (Ref: linting.md)
- [ ] **風格與型別確認**：你是否已在本地環境中，或在心中模擬執行過 `ruff check` 與 `mypy --strict`？
- [ ] **零妥協檢查**：確保沒有任何未使用的 imports，且絕對沒有為了便宜行事而使用 `Any` 或 `# type: ignore`。

## 2. 核心架構驗證 (Ref: core.md)
- [ ] **不可變與解耦**：資料模型是否預設使用了 `frozen=True`？介面是否優先採用了 `Protocol`？
- [ ] **日誌與錯誤防護**：全域搜尋你剛寫的代碼，**是否夾帶了任何 `print()` 或裸露的 `except Exception:`？** 如果有，立即將其改為 `logging` 與具體的商業異常。

## 3. 測試隔離驗證 (Ref: testing.md)
- [ ] **AAA 結構標記**：檢查你新增的測試代碼，是否嚴格包含了 `# Arrange`, `# Act`, `# Assert` 的區塊註解？
- [ ] **Fixture 乾淨度**：涉及狀態改變的 fixture 是否已使用 `yield` 並實作了 teardown 清理機制？嚴禁在測試內寫 `for` 迴圈。

## 4. 環境鎖定驗證 (Ref: env.md)
- [ ] **依賴變更合法性**：如果你在此次任務中新增了套件，是否是透過提示使用者執行 `uv add` 或使用專案內建工具完成的？**確保沒有建議使用 `pip`。**
- [ ] **配置注入**：是否確保沒有在業務邏輯中偷用 `os.getenv`？
