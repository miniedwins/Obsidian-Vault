# 程式碼解析與 AI 知識文件生成

當此 Skill 被觸發時，你的任務是主動引導使用者完成整個分析流程，
最終自動產出一份完整的 Markdown 知識文件。
不要等使用者一步一步問你，由你主導整個過程。

---

## 階段 0：收集前置資訊

觸發後，立即詢問使用者以下資訊（若對話中已提供則跳過）：

1. **程式語言**：Python、C、C++，還是混合？
2. **專案規模**：大概有幾個檔案？有沒有資料夾結構可以先提供？
3. **程式碼來源**：直接貼上程式碼，還是分批上傳？

根據語言確定「模組」的定義：
- Python → 一個 `.py` 檔案為一個模組
- C/C++ → 一個 `.h` + `.c/.cpp` 配對為一個模組

告知使用者接下來的流程，讓他知道你會主動帶領他完成分析。

---

## 階段 1：建立模組清單與依賴關係

收到程式碼後，主動執行以下分析（不需要使用者要求）：

**你必須產出：**

1. **模組清單表格**
   | 模組名稱 | 檔案路徑 | 一句話說明用途 |

2. **依賴關係表格**
   | 模組 | 依賴的模組 | 依賴類型（import / include / 繼承 / 呼叫）|

3. **Mermaid 依賴關係圖**（方向：A --> B 表示 A 依賴 B）
   ```mermaid
   graph TD
       A[模組A] --> B[模組B]
   ```

**分析技巧：**
- Python：從 `main.py` 或 `__init__.py` 追蹤 import 鏈
- C/C++：先讀 `.h` 標頭檔的 `#include`，再深入 `.cpp` 實作
- 若程式碼太大，請告知使用者分批提供，並說明先從哪個部分開始

完成後詢問使用者：「模組清單和依賴關係是否正確？有遺漏或需要調整的地方嗎？」

---

## 階段 2：核心模組分析

依賴關係確認後，主動執行核心模組分析：

**你必須產出：**

1. **核心模組排名表格**
   | 模組名稱 | 被依賴次數 | 耦合程度 | 重要程度（高/中/低）| 說明 |

2. **主要執行流程鏈**，用箭頭表示：
   ```
   進入點（main）→ 核心模組A → 核心模組B → 輸出
   ```

3. **耦合評估**：
   - 高耦合模組（修改它會影響很多地方）
   - 低耦合模組（可獨立替換或移除）

---

## 階段 3：模組職責卡片

針對每一個模組，主動產出以下格式的卡片。
**重要：分為兩層粒度，缺一不可。**

```
---
## 模組：[檔案名稱]

### 職責概述
一到三句話說明這個模組負責什麼。

### 模組關係
- 依賴：[它依賴的模組列表]
- 被依賴：[依賴它的模組列表]

### 對外函式（Public Interface）

#### `function_name(param1: 型別, param2: 型別) -> 回傳型別`
- 用途：一句話說明
- 參數說明：param1 — 說明；param2 — 說明
- 回傳值：說明回傳的內容
- 副作用：修改狀態 / 寫檔 / 呼叫外部（無則填「無」）
- 使用範例：
  ```python
  result = function_name(arg1, arg2)
  ```

### 私有函式（內部實作，不對外）
- `_func1()` — 簡短說明
- `_func2()` — 簡短說明
---
```

---

## 階段 4：自動產出知識文件

完成以上所有分析後，**不需要等使用者要求**，直接整合所有內容，
產出以下格式的完整知識文件，並儲存為 `{專案名稱}_knowledge.md`：

```markdown
# 專案知識文件：{專案名稱}

## 1. 專案概述
- 功能描述：（一句話）
- 程式語言：
- 技術棧：

## 2. 架構總覽
### 模組清單
（表格）

### 核心依賴關係圖
（Mermaid 圖）

## 3. 模組詳細說明
（所有模組卡片）

## 4. 常見使用情境
- 情境：如果要做 [某件事]
  → 模組：[名稱] → 函式：[名稱]
  → 範例：
  ```python
  # 程式碼
  ```

## 5. 注意事項
- 副作用警告
- 初始化順序要求
- 已知限制

## 6. 給 AI 的快速導引
（用一段話總結最重要的三個模組及其用途，
 讓新的 AI 在最短時間內掌握最關鍵的資訊）
```

## 階段 5：提供給未來 AI 的載入說明

知識文件產出後，告知使用者以下的快速載入方式：

> 當你要讓另一個 AI 理解這個專案時，在對話開頭貼上：
>
> 「以下是這個專案的知識文件，請閱讀後記住內容。
>  之後我問的問題請對應到文件中的模組與函式來回答。
>  [貼上知識文件]
>  請用一句話總結專案功能，並說出最重要的三個模組。」

## 執行原則

- **主動推進**：不要等使用者催促，完成一個階段後主動進入下一個
- **分批處理**：程式碼太大時，主動告訴使用者分批的策略（先哪個資料夾、再哪個）
- **確認關鍵節點**：階段 1 結束後確認依賴關係，其餘階段直接執行
- **語言一致**：全程使用繁體中文輸出
- **格式嚴格**：知識文件必須完整包含五個章節，不得省略
