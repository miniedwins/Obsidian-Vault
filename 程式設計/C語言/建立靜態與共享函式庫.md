## 靜態函式庫

**Example file : xyz.c**

```
#include <stdio.h>

void xyz() {
	printf("static lib: xyz\n");
}
```

編譯 `xyz.c` 的程式碼，產生 `xyz.o` 檔案。

```
$ gcc -c -o xyz.o xyz.c
```

使用 `ar` 指令將打包成靜態連結函式庫，產生 `libxyz.a` 檔案。

```
$ ar -rcs libxyz.a xyz.o
```

主程式編譯，使用 `libxyz.a` 靜態連結函式庫，並且編譯成 `main_static` 執行檔。

下列三種編譯方法皆可以使用

```
# -L. 指定當前路徑
$ gcc main.c -L. -lxyz -o main_static

# -L 指定路徑來源
$ gcc main.c -L /usr/local/lib/ -lxyz -o main_static

# 直接編譯 (靜態函式名稱要全名)
$ gcc main.c -libxyz.a -o main_static
```

注意 : 編譯還需要包含該靜態函式庫的標頭檔。

```
$ gcc main.c -L /usr/local/lib/ -lxyz -I /usr/local/include/ -o main_static
```

## 共享函式庫

編譯時加入 `-fPIC` 參數，產生共享函式庫所需要的 position independant code：

```
$ gcc -c -fPIC -o xyz.o xyz.c
```

使用 `gcc` 建立共享函式庫：

```
$ gcc -shared -Wl,-soname,libxyz.so.1 -o libxyz.so.1.0.0 xyz.o
```

然後建立一個不含版本號碼的 `.so` 連結檔，這個檔案是要給 `gcc` 在連結時所需要的函式庫檔案。

```
$ ln -s libxyz.so.1.0.0 libxyz.so
```

另外再建立一個執行時要用的連結檔 :

```
$ ln -s libxyz.so.1.0.0 libxyz.so.1
```

使用共享函式庫來編譯執行檔：

```
$ gcc main.c -L. -lxyz -o main_dynamic
```

或是這樣編譯也可以：

```
$ gcc main.c libxyz.so -o main_dynamic
```

編譯完成後，此時執行檔案後會無法成功。因為共享函式庫使用的時候會去查找 `/usr/lib` 以及 `/lib` 這兩個目錄下的函式庫，而我們產生的函式庫是在不在該預設目錄下，所以會執行會失敗。

因此有三種方法可以找到共享函式庫 :

- 方法 (1) :	
	- libxyz.so 放到 `/usr/lib` 或是 `/lib`
- 方法 (2) : 
	- export `LD_LIBRARY_PATH=<指定共享函庫路徑>:$LD_LIBRARY_PATH`
- 方法 (3) : 
	- 在 `/etc/ld.so.conf` 加入我們的建立的函式庫路徑，然後執行 `/sbin/ldconfig`

LD_LIBRARY_PATH  : 
- `LD_LIBRARY_PATH` 是 LINUX 環境變數。
- 主要用於指定查找共享函式庫 (動態函式庫) 時除了默認路徑之外的其他路徑。
- 重新開機後指定的路徑就會失效。
