## 問題
處理 API 返回的字段名稱與程式碼中使用的字段名稱不一致的情況。

## 解決方案
當 API 返回的字段名稱與程式碼中使用的字段名稱不一致時，可以使用 Pydantic 的別名功能來解決這個問題。具體來說，Pydantic 提供了以下兩種方式來處理字段名稱不一致的情況：

1. **使用 `Field` 的 `alias` 參數**：
    - 為每個字段手動指定別名，將 API 返回的字段名稱映射到程式碼中的字段名稱。        

## 範例說明
透過別名的設定，不需對 API 資料與 User 物件做 Mapping，直接創建 User 物件。 

```python
from typing import Optional
from pydantic import BaseModel, Field, ValidationError

class User(BaseModel):
    # API 返回 'user_name'，但程式碼裡用 'name'
    name: str = Field(alias='user_name')
    # API 返回 'userAge'，但程式碼裡用 'age'
    age: int = Field(alias='userAge')
    # 可選字段，API 返回 'email'，但程式碼裡用 'user_email'
    user_email: Optional[str] = Field(default=None, alias='email')

    @classmethod
    def from_api_data(cls, data: dict):
        """
        從 API 返回的數據創建 User 對象
        """
        return cls.model_validate(data)
```

- 使用 `model_validate` 解析 API 資料，確保資料符合模型定義。
- 使用 `model_dump(by_alias=True)` 輸出字典時，鍵名會使用 `alias` 的名稱輸出。

```python
api_data = {
    "user_name": "張三",
    "userAge": 25,
    "email": "zhangsan@example.com"
}

user = User.from_api_data(api_data)
print(user.name)          # 輸出: 張三
print(user.age)           # 輸出: 25
print(user.user_email)    # 輸出: zhangsan@example.com
print(user.model_dump(by_alias=True))  
# 輸出: {'user_name': '張三', 'userAge': 25, 'email': 'zhangsan@example.com'}
```

`user_email` 是一個可選字段，如果 API 資料中沒有提供 `email`，則默認為 `None`。

```python
api_data_missing_email = {
    "user_name": "李四",
    "userAge": 30
}

user_missing_email = User.from_api_data(api_data_missing_email)
print(user_missing_email.user_email)  # 輸出: None
print(user_missing_email.model_dump(by_alias=True))  
# 輸出: {'user_name': '李四', 'userAge': 30, 'email': None}
```

若是需要處理大量的別名，則需要對每個欄位都聲明一個別名（e.g., user_name -> UserName），非常麻煩。 這時候就可以通過設定別名生成器來批次完成。
