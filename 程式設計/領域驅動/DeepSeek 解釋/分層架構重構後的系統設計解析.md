## **1. 分層架構的核心目標**

### **(1) 解決傳統分層的問題**

- **傳統三層架構 (Controller-Service-DAO)**：
    
    - 業務邏輯散落在 Service 中，導致「貧血模型」。
        
    - 基礎設施細節（如資料庫、第三方服務）直接污染業務程式碼。
        
- **DDD 分層的改進**：
    
    - **領域層**封裝核心業務邏輯，保持純淨（無外部依賴）。
        
    - **應用層**協調領域邏輯與技術實現，避免業務規則分散。
        

### **(2) 各層職責與依賴關係**

|分層|主要組成|依賴關係|範例|
|---|---|---|---|
|**領域層 (Domain)**|Entity、Value Object、Domain Service|無外部依賴|`Account`、`Money`、`AccountTransferService`|
|**應用層 (Application)**|Application Service、Repository 介面、ACL 介面|依賴領域層，不依賴具體實現|`TransferServiceImpl`、`ExchangeRateService`|
|**基礎設施層 (Infra)**|Repository 實現、ACL 實現、Controller|依賴應用層和領域層，提供技術實現|`AccountRepositoryMySQL`、`KafkaAuditMessageProducer`|

## **2. 關鍵設計解析**

### **(1) 領域層：純業務邏輯的核心**

- **Entity (聚合根)**：

```java
public class Account {
    private AccountId id;
    private Money balance;
    
    // 領域行為：扣款
    public void debit(Money amount) {
        if (this.balance.isLessThan(amount)) {
            throw new InsufficientBalanceException();
        }
        this.balance = this.balance.subtract(amount);
    }
}
```

- **Domain Primitive (值物件)**：

```java
@Value
public class Money {
    private BigDecimal amount;
    private Currency currency;
    
    public boolean isLessThan(Money other) {
        assertSameCurrency(other);
        return this.amount.compareTo(other.amount) < 0;
    }
}
```

- **Domain Service**：

```java
public class AccountTransferService {
    public void transfer(Account source, Account target, Money amount, ExchangeRate rate) {
        Money convertedAmount = rate.convert(amount);
        source.debit(amount);
        target.credit(convertedAmount);
    }
}
```

### **(2) 應用層：協調與技術無關的流程**

- **Application Service**：

```java
public class TransferServiceImpl implements TransferService {
    private final AccountRepository accountRepository;
    private final ExchangeRateService exchangeRateService;
    
    @Override
    public Result transfer(Long sourceId, String targetNumber, BigDecimal amount, String currency) {
        // 參數轉換為領域物件
        Money targetMoney = new Money(amount, new Currency(currency));
        
        // 呼叫領域邏輯
        Account source = accountRepository.find(new AccountId(sourceId));
        Account target = accountRepository.find(new AccountNumber(targetNumber));
        ExchangeRate rate = exchangeRateService.getRate(source.getCurrency(), targetMoney.getCurrency());
        
        // 執行轉帳
        accountTransferService.transfer(source, target, targetMoney, rate);
        
        // 持久化與副作用
        accountRepository.save(source);
        accountRepository.save(target);
        auditMessageProducer.send(new AuditMessage(source, target, targetMoney));
        
        return Result.success();
    }
}
```

### **(3) 基礎設施層：技術細節的實現**

- **Repository 實現**：

```java
public class AccountRepositoryMySQL implements AccountRepository {
    @Override
    public Account find(AccountId id) {
        AccountDO accountDO = jdbcTemplate.queryForObject("SELECT * FROM accounts WHERE id = ?", id.getValue());
        return AccountMapper.toEntity(accountDO); // 轉換為領域物件
    }
}
```

- **ACL 實現**：

```java
public class YahooExchangeRateService implements ExchangeRateService {
    @Override
    public ExchangeRate getRate(Currency source, Currency target) {
        BigDecimal rate = yahooClient.getRate(source.getCode(), target.getCode());
        return new ExchangeRate(rate, source, target);
    }
}
```

## **3. 依賴注入與依賴方向**

### **(1) 依賴規則**

- **單向依賴**：  
    `Infrastructure → Application → Domain`
    
    - 基礎設施層依賴應用層的介面（如 `AccountRepository`）。
        
    - 應用層依賴領域層的物件（如 `Account`、`Money`）。
        

### **(2) 依賴注入實現**

- **Spring 範例**：

```java
@Service
public class TransferServiceImpl implements TransferService {
    // 依賴抽象介面
    private final AccountRepository accountRepository;
    private final ExchangeRateService exchangeRateService;
    
    // 通過構造器注入
    public TransferServiceImpl(
        AccountRepository accountRepository,
        ExchangeRateService exchangeRateService
    ) {
        this.accountRepository = accountRepository;
        this.exchangeRateService = exchangeRateService;
    }
}
```

## **4. 優勢與實際效益**

### **(1) 業務邏輯高內聚**

- 所有轉帳規則集中在 `Account` 和 `AccountTransferService` 中，而非散落在多個 Service。
    

### **(2) 技術細節可替換**

- 更換資料庫？只需實現新的 `AccountRepository`。
    
- 替換 Yahoo 匯率服務？新增 `FixerExchangeRateService`。
    

### **(3) 測試更容易**

- **領域層**：純記憶體測試，無需 Mock。
    
- **應用層**：Mock Repository 和 ACL 介面。

```java
@Test
void testTransfer() {
    AccountRepository mockRepo = mock(AccountRepository.class);
    when(mockRepo.find(any())).thenReturn(new Account(...));
    
    TransferService service = new TransferServiceImpl(mockRepo, ...);
    service.transfer(...);
    
    verify(mockRepo).save(any());
}
```

## **5. 進階應用：事件驅動與 CQRS**

### **(1) 發送領域事件**

```java
public class Account {
    public void debit(Money amount) {
        if (this.balance.isLessThan(amount)) {
            DomainEventPublisher.publish(new InsufficientBalanceEvent(this.id, amount));
            throw new InsufficientBalanceException();
        }
        this.balance = this.balance.subtract(amount);
        DomainEventPublisher.publish(new AccountDebitedEvent(this.id, amount));
    }
}
```

### **(2) 讀寫分離 (CQRS)**

- **寫模型**：使用領域層的 `Account` 聚合根。
    
- **讀模型**：透過 `AccountQueryService` 直接查詢 DTO。

## **6. 總結：分層架構的關鍵點**

1. **領域層是核心**：
    
    - 包含業務規則，無技術依賴。
        
2. **應用層是協調者**：
    
    - 組合領域邏輯，管理事務與副作用。
        
3. **基礎設施層是實現細節**：
    
    - 可替換，不影響上層。
        

**最終目標**：

> **「業務邏輯與技術實現分離，讓系統更容易應對變化。」**  
> 透過清晰的依賴方向，確保領域層的穩定性和可測試性。
