## 概述說明

**Asynchronous Event Request（異步事件請求）** 是 NVMe 協議中用於通知主機設備狀態、錯誤或健康資訊的重要機制。主機通過提交該命令，允許控制器在事件發生時主動通知主機。
## 事件運作原理

### 1. 事件請求

主機提交此異步事件請求命令，並且會持續等待直到控制器事件回報。若是事件尚未發生，提交的**命令不會超時 ( Time Out )**，也不會收到控制器回傳的 **CQE**。
### 2. 事件通知

當異步事件發生時，控制器完成主機所提交的 **AER命令** 並且向主機發送通知，透過 **CQE** 回傳作為通。主機收到該通知後，需要檢查 **CQE 的 Dword 0** 以了解具體的事件內容。並且根據事件通知所提供的 **LID、AEI、AET** 找到事件的類型與資訊。

- **Log Page Identifier ( LID )** : 
	- 表示與此事件相關的日誌頁面類型。
- **Asynchronous Event Information ( AEI )** : 
	- 提供有關具體事件的詳細信息。
	- **作用**：輔助主機進一步診斷事件原因。
- **Asynchronous Event Type ( AET )** : 
	- 描述事件的類型，用於區分事件的性質。

### 3. 事件處理與清除

當主機收到事件通知後，會根據事件中提供的 **LID（Log Page Identifier）**，使用 **Get Log Page 命令** 獲取具體的事件細節，並且執行清除事件操作，將事件標記為已處理。

主機端要如何清除事件 ? 透過執行 `Get Log Page` 並且將 **RAE** 位元設置為 `0`，代表事件清除。

![[Pasted image 20241129023907.png]]
### 4. 處理流程總結

1. 主機提交 **Asynchronous Event Request 命令**。
2. 控制器檢測事件並完成命令，生成完成隊列條目 **( Completion Queue Entry, CQE )** 。
3. 主機從 CQE 提取事件資訊，執行 **Get Log Page 命令** 獲取詳細數據。
4. 主機處理事件後，設置 RAE = 0 清除事件。

追蹤  `NVMe TRACE` 當主機端收到 **CQ Entry Dword0 : `0x00040002`**，表示控制器通知了一個 **Namespace Changed** 的事件。以下是該事件的詳細解析：

![[Pasted image 20241202062500.png]]

**解析事件**：
- 確認 LID : `0x04` ( **Namespace Changed Log Page** ，表示相關日誌頁)
- 確認 AEI : `0x00` ( **Attached Namespace Attribute Changed**，表示命名空間發生了變化。)
- 確認 AET : `0x02` ( 表示事件類型為 **Notice**，即通知類型事件。)

從事件的通知說明，主要命名空間 ( Namespace ) 屬性發生變化，就會發通知給主機端。

事件資訊的內容會回報主機，`Namsapce Data Structure` 發生了改變，此時的主機端可能會重確認目前所有 `Namespaces` 狀態，並且做出相對應的處理流程。

目前從 `NVMe Trace` 可以得知，主機端會發出 **List Namesapce ( Attached )** 以及 **Identify Namesapce List**，來取得當前所有 Namespaces 狀態。

## 事件清除補充說明

根據 NVMe 規範，當沒有未完成的 AER 命令時，控制器需要處理和保留異步事件的資訊，並在後續的 AER 命令中進行回報。以下是具體行為的說明：

 **(1) 當事件發生時，且沒有未完成的 AER 命令**

 如果某類型的事件已經發生，但當時主機端沒有發送任何正在等待的 AER 命令，控制器會將此異步事件的資訊保留起來，並在下一次收到 AER 命令時，將其作為回應的一部分。

 **(2) 事件清除的條件**

當以下情況發生時，事件通知將不再發送：

- **Get Log Page 命令清除了事件**：如果主機在發送 AER 命令前，通過 `Get Log Page` 命令清除了該事件的資訊，則控制器不會再報告該事件。

- **控制器級別的重置**：若發生 `Controller Level Reset`，保留的事件資訊也會被清除。

**(3) 多個相同類型事件的處理**

-  **相同類型、相同回應的多個事件**：如果發生多個相同類型且回應完全相同的事件，控制器可以將這些事件合併，並以單一回應的形式報告給 AER 命令。

- **不同類型或不同回應的多個事件**： 如果事件類型不同，或即使是相同類型但回應內容不同，控制器需要保留一個事件隊列。 控制器將這些事件逐一分批報告，回應後續的 AER 命令。
## 控制器重置的影響

- 如果控制器在異步事件尚未發生前被重置，所有尚未完成的 **AER命令** 會被 **中止（Abort）**。
- 對於這些被中止的命令，控制器不會生成 **CQE**。
- 主機需要在重置後重新提交新的 **AER命令**，以恢復事件通知功能。
