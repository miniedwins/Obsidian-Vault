## 概述說明

- 用於通知主機有關設備的 **狀態、錯誤和健康資訊**。
- 當事件（如溫度警告、健康狀態變化）發生時，控制器通過完成隊列條目（CQE）通知主機。
## 工作流程

主機會提交此異步事件請求，當主機收到控制器回傳的事件通知後，會根據事件中提供的 **LID、AEI、AET** 資訊，使用 **Get Log Page 命令** 獲取具體的事件細節，並且將事件標記為已處理。
## 運作原理

### 1. 事件請求

主機提交此異步事件請求命令，並且會持續等待直到控制器事件回報。若是事件尚未發生，提交的命令並不會超時，也不會收到控制器回傳的 CQE。
### 2. 事件通知

當異步事件發生時，控制器會完成主機所提交的 **AER命令** 並且向主機發送通知。該通知是透過 **完成（Completion Queue Entry, CQE）** 回傳的。主機收到該通知後，需要檢查 **CQE 的 Dword 0** 以了解具體的事件內容。並且根據事件通知所提供的 **LID、AEI、AET** 找到事件的類型與資訊。
### 3. 事件類型

- **Log Page Identifier (LID)** : 表示與此事件相關的日誌頁面類型。
- **Asynchronous Event Information (AEI)** : 提供有關具體事件的詳細信息。
- **Asynchronous Event Type (AET)** : 描述事件的類型，用於區分事件的性質。

每一個事件類型內，包含許多事件的資訊，這裡我們使用 `Notice` 作為一個範例說明。

假如當主機端收到 **CQ Entry Dword0 : `0x00040002`**，表示控制器通知了一個 **Namespace Changed** 的事件。以下是該事件的詳細解析：

- LID : 0x04 ( 對應 **Namespace Changed Log Page** )
- AEI : 0x00 ( 表示 **Attached Namespace Attribute Changed**，命名空間發生了變化。)
- AET : 0x02 ( 表示事件類型為 **Notice**，即通知類型事件。)

### 3. 事件處理與清除

根據 NVMe 規範，當沒有未完成的 AER 命令時，控制器需要處理和保留異步事件的資訊，並在後續的 AER 命令中進行回報。以下是具體行為的說明：

 **1. 當事件發生時，且沒有未完成的 AER 命令**
 如果某類型的事件已經發生，但當時沒有任何正在等待的 AER 命令，控制器會將此異步事件的資訊保留起來，並在下一次收到 AER 命令時，將其作為回應的一部分。

 **2. 事件清除的條件**
當以下情況發生時，事件通知將不再發送：
- **Get Log Page 命令清除了事件**：如果主機在發送 AER 命令前，通過 `Get Log Page` 命令清除了該事件的資訊，則控制器不會再報告該事件。
- **控制器級別的重置**：若發生 Controller Level Reset，保留的事件資訊也會被清除。

**3. 多個相同類型事件的處理**
-  **相同類型、相同回應的多個事件**：
    - 如果發生多個相同類型且回應完全相同的事件，控制器可以將這些事件合併，並以單一回應的形式報告給 AER 命令。
- **不同類型或不同回應的多個事件**：
    - 如果事件類型不同，或即使是相同類型但回應內容不同，控制器需要保留一個事件隊列。
    - 控制器將這些事件逐一分批報告，回應後續的 AER 命令。

## 控制器重置的影響

- 如果控制器在異步事件尚未發生前被重置，所有尚未完成的 **Asynchronous Event Request 命令** 會被 **中止（Abort）**。
- 對於這些被中止的命令，控制器不會生成 CQE。
- 主機需要在重置後重新提交新的 **Asynchronous Event Request 命令**，以恢復事件通知功能。
