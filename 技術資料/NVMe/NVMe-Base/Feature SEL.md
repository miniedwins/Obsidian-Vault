1. 為什麼不能「支援 Saveable，但不支援 Changeable」？

- **Changeable = 0**：代表這個 Feature 的值是**唯讀的（Static / Fixed）**，主機完全無法透過 `Set Features` 變更它，它的值永遠等於出廠預設值（Default Value）。
- **Saveable = 1**：代表主機可以變更值，並要求控制器將「新變更的值」保存到非揮發性儲存空間中。
- 如果一個功能根本不允許主機修改（`Changeable = 0`），那主機就沒有任何新值可以儲存。因此，**不允許修改的 Feature，其** **Saveable** **必定也為** **0**。如果主機強行對一個 `Changeable = 0` 的 Feature 發送 `Set Features`（不論 SV 位元是否為 1），控制器都會直接 Abort 該指令並回傳 **Feature Not Changeable** 狀態碼。

2. 常見的位元組合與代表意義

在 NVMe 規格書中，位元的組合只有以下三種合法情境：

| Changeable (Bit 2) | Saveable (Bit 0) | 類型說明與實務範例                                                                                                                                                |
| ------------------ | ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **0**              | **0**            | **完全不可變、亦不可保存（唯讀）**：<br>例如某些唯讀的硬體屬性，主機只能 Get，不允許 Set。                                                                                                    |
| **1**              | **0**            | **可修改，但不可保存（暫存型/揮發性）**：<br>主機在執行期間可以任意修改（Current Value），但只要斷電或 Reset 就會恢復預設值。例如 **Host Metadata (7Dh/7Eh/7Fh)**、**Host Identifier (81h)** 等。             |
| **1**              | **1**            | **可修改，且支援永久保存（保存型/非揮發性）**：<br>主機修改後，若下達 `SV = 1`，控制器會將其存入 Flash，下次開機自動套用此新值。例如 **Power Management (02h)** 或 **Arbitration (01h)** 等（前提是控制器有宣告支援 `SSFS`）。 |
