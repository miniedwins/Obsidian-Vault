# 概要說明

日誌格式可以讓我們知道自檢運行的進度以及結果。
# 日誌結構

- 日誌運行的狀態共佔 ( 4 bytes ) : 
	- [ 01:00 ] Bytes : 永遠表示當前自檢的類型與進度 
	- [ 03:02 ] Bytes : 保留位元
* 一個日誌總共佔 ( 28 bytes ) : 
	* [ 31:04 ] Bytes : 表示第一筆日誌內容

* 控制器可以儲存 `20` 條日誌訊息 
* 全部日誌資料 :  4 + ( 28 x 20 Entry ) = 564 Bytes
* 最新自檢的日誌會放在第一個 ( 1st )。
* 若是超過最大儲存，最後一個 ( 20th ) 日誌會被前一個 ( 19th ) 取代。
# 取得自檢日誌

- 執行命令 `nvme-cli`，選擇那一種顯示方式較為方便閱讀日誌。

~~~shell
# NORMAL 格式輸出
nvme self-test-log /dev/nvme0 -o "normal"

# JSON 格式輸出
nvme self-test-log /dev/nvme0 -o "json"
~~~
# 解析基本日誌

- **NVMe-CLI 輸出結果說明** : 
	- 只挑選比較重要的內容顯示。
	- 每一條日誌所輸出的結果並非日誌完整的訊息。

- **日誌說明 :** 
	- Current Operation : 
		- 數值 : `0%`
		- 結果 : 代表當前並沒有任何自檢測試在運行
	- Current Completion :
		- 數值 : `0%`
		- 結果 : 代表當前並沒有任何自檢測試在運行
	* Self Test Result [0] : 
		* 代表第一條日誌，以此類推
		* Operation Result : 
			* 數值 : `0`
			* 結果 : 代表沒有發生錯誤
		* Self Test Code :
			* 數值 : `2`
			* 結果 :  Extended Self Test
		* Valid Diagnostic Information :
			* 數值 : `0`
			* 疑問 : 不清楚想表達的意義
		* Power on hours ( POH ) :
			* 數值 : `0x288` 
			* 結果 : 執行第一次自檢測試開始，到現在 `SSD` 總共上電多少個小時
		* Vendor Specific :  
			* 數值 : `0 0`
			* 結果 : 代表沒有發生錯誤
			* 未確定 : 應該表示廠商自定義的自檢測試

# 解析完整日誌

- 若是要取得完整的資訊，需要輸出二進制檔案。
- 使用 `hexdump` 查看，這裡僅顯示 512 Bytes 做範例說明。

~~~shell
# 將日誌以二進位輸出到 "self_test.log" 檔案
nvme self-test-log /dev/nvme0 -o "binary" > self_test.log

# 使用 hexdump 命令，它會以16進位的方式顯示
hexdump -C -n 512 self_test.log

# 或是直接使用 get-log
nvme get-log -i 0x06 -l 563
~~~

- 自檢日誌主要觀察這兩個項目 : 
	- **Device Self Test Log**
		- 表示當前測試的操作與進度。
	- **Self-Test Result Data Structure**
		- 說明自檢測試的結果。
## Device Self-Test Log

- **Current Device Self-Test Operation** : 
	- 表示當前自檢的類型。
- **Current Device Self-Test Completion** :
	- 目前自檢進度百分比。

## Self-Test Result Data Structure

- 主要觀察這兩個項目，其它在參考圖示說明
	* **Device Self-test Status** : 
		* [ 07:04 ] Bits : 自檢測試的類型。
		* [ 03:00 ] Bits : 自檢測試的結果。
	* **Segment Number** : 
		* 發生自檢錯誤，是哪個測試項目錯誤 **( 對應自檢測試項目編號 )**。
		* **Device Self-Test Status** : 
			* 設定的值設定為 **7h** ，表示有一個或多個測試失敗了。
			* 設定的值不是 **7h**，完全可以忽略。
