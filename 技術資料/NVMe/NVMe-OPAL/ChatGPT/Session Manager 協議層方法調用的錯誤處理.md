### **1. Session Manager 協議層方法調用的錯誤處理**

- **識別但失敗的方法調用**：
    
    - 如果 **Session Manager 協議層** 識別了方法調用，但執行失敗，**TPer** 應返回該方法的正常響應格式，並附帶錯誤狀態碼。
        
    - 這意味著響應的結構與成功時相同，但包含錯誤狀態碼。
        
- **會話啟動方法（Session Startup Methods）**：
    
    - 如果會話啟動方法失敗，**TPer** 應返回預期的方法響應，但僅包含識別參數（例如 **Host** 和 **SP**）和錯誤狀態碼。
        
    - 示例：`{Host=0x1234, SP=0x5678, status=INVALID_SESSION}`
        
- **無效的識別參數**：
    
    - 如果識別參數（特別是 **Host** 參數）無效（例如類型錯誤），**TPer** 可以忽略該方法。
        

---

### **2. 不同點的解釋**

以下是 **Session Manager 協議層方法調用** 的錯誤處理與其他情況的不同點：

#### **(1) 與無法識別的方法調用的區別**

- **無法識別的方法調用**：
    
    - 如果 **TPer** 無法識別方法調用，則根據會話類型（Regular 或非 Regular）進行處理：
        
        - 在 **Regular 會話** 中，返回空結果和錯誤碼。
            
        - 在 **非 Regular 會話** 中，忽略該調用，並且不發送任何響應。
            
- **Session Manager 協議層方法調用**：
    
    - 即使方法調用失敗，**TPer** 也應返回正常響應格式，並附帶錯誤狀態碼。
        
    - 這與無法識別的方法調用不同，後者可能返回空結果或忽略調用。
        

#### **(2) 與其他方法調用的區別**

- **其他方法調用**：
    
    - 對於其他方法（例如 **SP** 方法），如果方法調用失敗，**TPer** 應返回空結果和錯誤碼。
        
    - 這與 **Session Manager 協議層方法調用** 不同，後者返回正常響應格式。
        

#### **(3) 會話啟動方法的特殊處理**

- **會話啟動方法**：
    
    - 如果會話啟動方法失敗，**TPer** 應返回預期的方法響應，但僅包含識別參數和錯誤狀態碼。
        
    - 這與其他方法調用不同，後者可能返回完整的結果或空結果。
        

---

### **3. 示例場景**

以下是幾個典型場景的示例，展示不同情況的處理方式：

#### **(1) Session Manager 協議層方法調用失敗**

- 方法調用：`StartSession`
    
- 響應：
    
    - `{Host=0x1234, SP=0x5678, status=INVALID_SESSION}`
        

#### **(2) 無法識別的方法調用**

- 方法調用：`UnknownMethod`（在 Regular 會話中）
    
- 響應：
    
    - `{result=[], status=UNRECOGNIZED_METHOD}`
        

#### **(3) 其他方法調用失敗**

- 方法調用：`SetConfiguration`（在 **SP** 中）
    
- 響應：
    
    - `{result=[], status=INVALID_PARAMETER}`
        

---

### **4. 總結**

- **Session Manager 協議層方法調用** 的錯誤處理與其他情況不同：
    
    - 即使方法調用失敗，**TPer** 也應返回正常響應格式，並附帶錯誤狀態碼。
        
    - 會話啟動方法失敗時，僅返回識別參數和錯誤狀態碼。
        
- 無法識別的方法調用和其他方法調用的錯誤處理方式不同，可能返回空結果或忽略調用。
