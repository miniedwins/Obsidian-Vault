# 一、這個模板「本質是什麼？」

`Reject <Action> When <Precondition Violates Constraint>`

這不是只是英文句型，而是一個**測試語意骨架（Semantic Skeleton）**：

|元素|本質角色|
|---|---|
|`<Action>`|系統「想做但被禁止的行為」|
|`<Precondition>`|當下狀態 / 已存在條件|
|`<Constraint>`|規範 / 不可被違反的限制|

👉 換句話說：  
**「在某個狀態下，因為違反某個規則，所以某個行為必須被拒絕」**

這正是：

- 測試案例
    
- Spec 驗證
    
- Negative path
    
- Compliance test
    

的共同語言。

---

# 二、怎麼「人類實際使用」這個模板（寫測試）

### ① 先填中文（強烈建議）

不要一開始就寫英文。

`Reject <Action> When <Precondition Violates Constraint>`

➡️ 轉成中文骨架：

`拒絕 <行為> 當 <前置條件 違反 某個限制>`

### ② 套用到你的實際案例（你剛剛那個）

|Slot|填入內容|
|---|---|
|Action|Enabling MBRControl|
|Precondition|Target Namespace exists|
|Constraint|MBR format is incompatible with LBA format|

➡️ 自然語言展開：

`Reject Enabling MBRControl When the MBR Format Is Incompatible with the Namespace LBA Format`

這一步 **人就完成了**。

# 三、怎麼「用在提示詞（Prompt）」上

這裡才是重點 🔥  
你可以**直接把這個模板變成 AI 的思考框架**。

---

## 🧠 Prompt 範例 1：強制 AI 用此語意產生 Title

`You are a test case reviewer.  Use the following semantic template to generate test case titles:  Template: Reject <Action> When <Precondition Violates Constraint>  Rules: - <Action> must be a controllable system behavior - <Precondition> must describe an existing state - <Constraint> must be a violated specification rule  Input: - Action: Enable MBRControl - Precondition: Target Namespace exists - Constraint: MBR format is incompatible with LBA format  Output: - One test case title only.`

👉 **AI 幾乎不可能跑偏**。

---

## 🧠 Prompt 範例 2：丟中文敘述，讓 AI 自動抽 Slot

`You are a test case semantic parser.  Given a test description, extract: - Action - Precondition - Constraint  Then generate a test title using this template:  Reject <Action> When <Precondition Violates Constraint>  Test description: 當指定的 Namespace 存在，但其 MBR 格式與 LBA 格式不相容時，控制器可能拒絕啟用 MBRControl。`

這其實就是一個**結構化 Prompt**。

---

# 四、這就是 Context Engineering（不是寫 Prompt 而已）

你現在看到的是 **「語意 Context」** 的用法。

### 傳統 Prompt

> 幫我改 title

👉 AI 靠猜

---

### Context Engineering 版

你先提供：

1. **語意模板（Invariant）**
    
2. **角色定義（Reviewer / Parser）**
    
3. **Slot 規則**
    
4. **輸出限制**
    

👉 AI 只能在你定義的語意空間裡移動

---

## Context 範例（你可以長期重用）

`[Context] All negative test cases must follow a semantic invariant:  Reject <Action> When <Precondition Violates Constraint>  Definitions: - Action: a system operation under test - Precondition: an existing system state - Constraint: a specification rule that must not be violated  The title must: - Express causality - Avoid ambiguous verbs (e.g., "handle", "process") - Be grammatically correct and spec-oriented`

你之後丟 **任何測試案例** 進來，AI 都會被「語意框住」。

# 五、進階：你其實在做「規格 → 語言 → 測試」的橋接

你這個模板本質上是：

`SPEC Rule Violation     ↓ Causal Language Pattern     ↓ Test Case Title`

這就是為什麼你會一直覺得：

> 「不是英文問題，是語意一致性問題」

因為你已經在做 **Spec-level 思考**。
